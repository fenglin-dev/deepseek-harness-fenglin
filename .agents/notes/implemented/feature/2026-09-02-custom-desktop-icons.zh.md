# Agent Note: 自定义桌面图标由应用宿主本地持有

Status: implemented

[English](2026-09-02-custom-desktop-icons.md) | 中文

## 问题

用户需要易于辨识的应用和托盘图标，同时不改变 Harness 配置，也不修改签名后的应用包。操作系统提供的运行时与快捷方式图标机制不同，因此一次 API 调用成功不能证明所有系统位置都已变更。

## 决策

规范化裁剪图是派生展示图的来源，而非最终系统图标。512px 画布在 macOS 中容纳 412px 应用图案，圆角半径为 92px；Windows 与自定义托盘使用 480px 图案及 80px 圆角半径。预览使用相同几何规则。原生渲染对预乘像素施加遮罩，保留透明度并平滑边缘。派生图缓存避免状态读取反复计算；启动始终从裁剪图生成一次，不会反复缩小已生成的结果。Windows 另写内容寻址的圆角 ICO，保留原始裁剪资源和已有快捷方式引用。

桌面图标管理器拥有图片解码、方形裁剪、规范化 PNG/ICO 资源及 Electron `userData/icons` 内的原子选择记录。它只接受字节与像素限制内的 PNG/JPEG 签名，在一次性应用 JPEG 方向前移除方向元数据，并验证方形裁剪坐标。图片选择 ID 不透明、绑定渲染窗口、只能使用一次且十分钟后过期。图片与哈希先于状态文件重命名落盘；生成或持久化失败时继续使用旧偏好。启动在创建窗口与托盘前解析已保存图片，损坏资源独立回退并报告异常。

Windows 保留 AppUserModelID，只更新当前用户中经验证指向运行实例的快捷方式。用户另外设置的图标、公共快捷方式、已固定任务栏链接、其他安装实例及符号链接不会被改写。macOS 使用运行时 Dock 与 Tray API，不修改应用包。自定义托盘图片保留原色；[专用模板图标决策](../bug-fix/2026-08-20-macos-tray-template-icon.zh.md) 继续拥有默认图形及其视觉几何。该记录保持活动，因为自定义上传不取代其设计理由。

通用设置拥有裁剪编辑器，并按系统目标位置报告结果。裁剪移动使用指针捕获与动画帧节流，支持方向键定位和对话框内的焦点循环。确认只向 Electron 发送选择 ID、固定用途及裁剪区域。操作不会重启 Harness。Linux 和 Web 不显示编辑器。

## 考虑过的替代方案

**改写应用资源。** 修改 macOS 应用包或 Windows 可执行文件会影响签名和升级。运行时 API 与自有快捷方式无需改变这些产物即可实现所需的个性化。

**存入 Harness 设置或插件快照。** 这样会把设备外观绑定到共享 Profile 和回退操作。桌面 `userData` 让开发版与安装版选择独立，并在 `DSH_HOME` 变化时保持不变。

**把所有系统更新视为一次成功。** Windows 可能保留已固定快捷方式的图标，或拒绝某个链接更新。独立结果可保留有效本地偏好，同时提供重试与重新固定说明。

## 验证

Desktop 聚焦测试覆盖选择权限、过期、取消、损坏资源、拒绝符号链接、原子保存中断、托盘跟随语义、ICO 帧、裁剪边界和快捷方式归属。客户端测试覆盖确认/取消、键盘裁剪、预览、提示、独立托盘选择及分位置结果。`apps/desktop/scripts/icon-native-smoke.mjs` 在临时目录使用真实 Electron 验证 PNG 透明度、JPEG EXIF 旋转、Dock/窗口与托盘替换/恢复及持久化。Windows 安装版快捷方式、任务栏固定、权限和升级重应用仍需原生发布验收。

## 后果

个性化保持本地，不改变内部品牌、通知、安装器、Finder 或插件状态。内容寻址的派生图标使现有受管快捷方式引用继续有效；只保留规范化输出，不保留来源路径。系统失败可见且可重试，不会丢弃有效图片。默认菜单栏模板继续适配系统外观，而自定义彩色图片的可读性由用户选择负责。

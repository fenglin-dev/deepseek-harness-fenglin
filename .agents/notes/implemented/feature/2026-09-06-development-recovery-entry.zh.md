# Agent Note: 启动恢复页面的开发入口

Status: implemented

[English](2026-09-06-development-recovery-entry.md) | 中文

## 问题

启动恢复页面通常只在真实启动失败后出现。维护者无法在不构造损坏 Profile 或等待启动监管器失败的情况下，检查其中的快照、数据目录、日志及返回行为。

## 决策

源码构建会在桌面桥中报告一项开发恢复能力，并在“通用设置”中显示对应操作。渲染层发送不带参数的请求。Electron 只会在请求来自可信主渲染进程、当前 Harness 已就绪且应用不是安装版时接受请求，然后使用固定开发文案与当前受管日志路径打开既有启动失败页面。该操作不会停止 Harness、修改 Profile 或伪造监管器故障。点击“重试”时，Electron 会识别仍然就绪的 Harness，并返回其已认证页面。

安装版的主进程会拒绝此能力，而不只是依赖客户端界面隐藏。即使过期或被修改的客户端 Bundle 尝试调用预加载方法，安装版也不会允许进入诊断模拟页面。

## 考虑过的替代方案

**注入真实插件或 Profile 故障。** 这种方式可以覆盖更多失败链路，但会让界面检查变成破坏性操作，并可能遗留恢复状态。

**直接重启到诊断安全 Profile。** 安全模式验证的是另一套启动组合，不能检查渲染进程无法加载时显示的独立页面。

## 后果

维护者可以从健康开发会话进入真实恢复页面，并再返回客户端。该预览只验证恢复界面及其桌面端操作；启动失败识别和诊断安全启动仍由现有测试与演练场景覆盖。

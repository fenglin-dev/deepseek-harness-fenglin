# Agent Note: 启动恢复页面的开发入口

Status: implemented

[English](2026-09-06-development-recovery-entry.md) | 中文

## 问题

启动恢复页面通常只在真实启动失败后出现。维护者无法在不构造损坏 Profile 或等待启动监管器失败的情况下，检查其中的快照、数据目录、日志及返回行为。

## 决策

源码构建会在桌面桥中报告一项开发恢复能力，并在“通用设置”中显示对应操作。渲染层发送不带参数的请求。Electron 只会在请求来自可信主渲染进程、当前 Harness 已就绪且应用不是安装版时接受请求，然后使用固定开发文案与当前受管日志路径打开既有启动失败工作区。单纯进入不会停止 Harness、修改 Profile 或伪造监管器故障。点击“继续”时，Electron 会识别仍然就绪的 Harness，并返回其已认证页面。

启动页与恢复工作区共用同一套冷中性色窗口、应用标识和确定型蓝色进度条。失败时进度条暂停，四个相互独立的工具在原位置展开。首页把插件管理、快照回退、配置目录切换与脱敏诊断导出作为并列选项；进入工具后，首页会由四个持续显示的栏目替代，用户无需返回上一步即可直接切换。

插件管理只读取 Web Profile 的直接依赖与安装方 Bundle 数量。Electron 只接受清单中仍然存在的包名，调用普通且有时限的 `dsh plugin --profile web remove` 前先停止 Harness，并在用户继续卸载其他插件时保持暂停；点击“继续”后由监管器恢复 Harness。核心 Bundle 永远不会出现在卸载操作中，本地包路径不会进入渲染层，每次普通 CLI 卸载仍会保留变更前自动插件快照。诊断导出由主进程管理，只包含应用与平台元数据、有长度限制的启动状态、脱敏故障文本及不含路径的插件清单。

安装版的主进程会拒绝此能力，而不只是依赖客户端界面隐藏。即使过期或被修改的客户端 Bundle 尝试调用预加载方法，安装版也不会允许进入诊断模拟页面。

## 考虑过的替代方案

**注入真实插件或 Profile 故障。** 这种方式可以覆盖更多失败链路，但会让界面检查变成破坏性操作，并可能遗留恢复状态。

**直接重启到诊断安全 Profile。** 安全模式验证的是另一套启动组合，不能检查渲染进程无法加载时显示的独立页面。

## 后果

维护者可以从健康开发会话进入真实恢复工作区，并再返回客户端。真实启动失败的用户可以直接切换各项恢复工具、卸载一个或多个外部插件，也可以不做修改直接继续。更宽的独立页面会增加预加载 Bundle 的界面代码，但文件系统路径、插件命令与诊断载荷仍全部由 Electron 管理。开发入口用于验证界面及桌面端操作；启动失败识别和诊断安全启动仍由现有测试与演练场景覆盖。

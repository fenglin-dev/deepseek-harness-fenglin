# Agent Note: 桌面宿主驻留与 Release 发现

Status: implemented

[English](2026-08-20-desktop-shell-residency-and-release-discovery.md) | 中文

## Problem

打包桌面宿主会随唯一窗口退出，无法登录启动，也没有原生生命周期通知；只有 Harness 耗尽启动重试后才会显示诊断入口。现有更新器面向受信任源码 checkout，而非打包 Release，因此用户也看不到应用版本更新信号。

## Decision

Electron 主进程拥有 `userData` 下的一份持久偏好文件、一套串行应用生命周期和一个系统托盘。默认关闭窗口只隐藏窗口，显式退出则等待 Harness 关闭。用户可通过受限 preload bridge 切换关闭行为、原生生命周期通知和已打包 macOS 的登录启动；不支持的平台把登录启动报告为不可用。偏好开关在开启时使用应用蓝色 token，关闭时使用自适应中灰色，两种状态都使用白色滑块，确保在明暗主题下都能清楚辨认状态。

连接页等待十五秒后显示固定 Harness 日志入口，但不会把缓慢启动判为失败。主进程只定位这份已知文件或其父目录，不接受渲染进程提供的路径。重启、连续失败与恢复通知采用操作系统语言，并按事件种类节流。

打包应用查询 `flaqai/open-deepseek-harness-desktop` Releases，并通过 preload bridge 暴露规范化状态。预发布客户端跟随当前预发布通道，也可迁移到更高的稳定版；稳定版忽略预发布。桌面侧边栏由该入口隐藏插件提供的其他页脚快捷按钮，仅在有更新时渲染一个 Release 操作，并在其图标右上角显示一个蓝色圆点；“通用设置”继续保留详细状态与手动检查。在 macOS 与 Windows 上，主进程按当前平台和架构选择固定命名的产物，并下载到 `userData`。安装包和校验文件的首个请求使用 Electron 的 Chromium 网络栈，以继承系统代理、PAC 和代理认证。连接失败、响应超时、响应体中断、HTTP 408 或服务器错误会切换一次到固定的 GitHub Asset API 端点。同一次下载中的安装包中断会使用经过验证的字节范围；若备用响应不支持该范围，则从第零字节重新下载；取消下载或退出应用会删除未完成文件。主进程发布这些状态，校验附件大小与 GitHub digest 或 `SHA256SUMS` 条目，并只允许操作系统打开通过校验的安装包。Linux 继续使用经过仓库校验的 Release 页面链接，因为同一 Release 同时提供 DEB 与 RPM。应用绝不自行替换自身，源码运行继续使用独立的受信任 checkout 更新器。

## Alternatives considered

**静默自动更新。** 未签名 Windows 产物和 ad-hoc 签名、未公证的 macOS 产物不具备无人值守替换所需的签名与回退保证。应用负责下载和校验安装包，但把替换、取消和冲突处理交给操作系统。

**使用第三方下载镜像。** 镜像会引入另一个发布权威，并可能与已撤回或替换的 GitHub 附件发生漂移。两个下载路径都继续绑定所选 GitHub Release 及其经过验证的大小和 SHA-256。

**把桌面偏好存入 Harness settings。** 关闭和登录启动行为必须在 Web 客户端连接前可用，因此 Electron 持有一份小型独立文件，只暴露类型化偏好操作。

**默认关闭即退出。** 这会意外停止后台任务和受监管 Harness。托盘驻留为默认行为，同时持久偏好保留明确的关闭即退选择。

## Consequences

桌面进程可以在没有可见窗口时保持活动，因此每条显式退出路径都必须汇入同一套异步 Harness 清理。原生托盘文案跟随操作系统语言，而非 Web 语言。登录启动刻意只支持 macOS。Release 发布必须保留固定安装包名称、有效的 GitHub 附件 id 和至少一种 SHA-256 来源；缺少校验数据或校验不匹配时操作会失败关闭。两个下载路径可以改善代理和受限网络的兼容性，但仍可能同时不可达。未完成文件只会在同一个运行中下载操作切换传输路径时保留。下载的安装包占用桌面数据目录空间，在具备签名发行与回退前，应用替换仍由用户手动完成。

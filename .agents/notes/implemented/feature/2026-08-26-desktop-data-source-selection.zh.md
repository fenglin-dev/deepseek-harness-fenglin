# Agent Note: 经验证的桌面端数据来源选择

Status: implemented

[English](2026-08-26-desktop-data-source-selection.md) | 中文

## Problem

首次启动的桌面端选择页把默认 `~/.dsh` 中任何非空内容都视为官方 Harness 数据，并在该目录不存在或为空时完全跳过选择页。使用自定义 `DSH_HOME`、便携目录或备份的用户无法选择自己的位置，无关文件却可能错误开放导入与复用操作，直到后续阶段才失败。

## Decision

桌面端独立 Harness home 没有既有选择或数据时，选择页始终打开。首页分为官方 DeepSeek Harness 配置、已有 Open DeepSeek Harness Desktop 配置与全新开始；两类已有来源分别记住所选目录。一个来源面板同时展示两类识别结果，并分别提供目录选择入口。开发版自动检查安装版桌面根目录，安装版自动检查开发目录，因此候选来源不会与本次首次启动的空目标重叠。识别到默认来源时，官方来源预选导入到独立环境，社区来源预选复制到独立环境；默认来源缺失或无法读取时预选全新开始，同时允许用户通过目录选择器选择对应的导入、复制或直接使用。

Electron 负责目录选择与验证。来源目录自身或其 `.dsh` 子目录包含受支持用户数据或 Profile 时才会被识别。社区来源优先通过 `data-home-setup.json` 读取活动 home 的绝对路径；记录无效或目标缺失时拒绝选择，不回退到旧数据。没有记录时可识别 `dsh-home` 子目录或实际 Harness home。渲染层只向验证过发送者的目录选择接口提交 official/community 类别。导入与全新开始另有独立的目标目录步骤：默认选中桌面版管理的位置，用户也可选择一个既有空文件夹。渲染层只接收短期不透明的目标标识，不能伪造路径；用户确认界面展示的路径后，Electron 会再次解析来源并检查目标仍为空。非空、无关、无法读取或已过期的选择会留在选择页，并显示范围明确的修正提示。

源码开发模式提供一个双语切换按钮，可临时呈现真实的“默认来源缺失”状态。该开关只在内存中保留检测到的来源与当前选择，关闭后恢复两者，也不会修改已保存的设置。安装版不会收到开发能力标记，因此始终隐藏该控件。

独立导入或复制会从检测到的默认来源或用户选择的自定义来源，复制到默认目标或自定义空文件夹目标。官方 DeepSeek Harness 来源执行兼容导入，只重置新副本的首次引导状态；社区桌面版来源完整复制 home，保留原有引导状态。直接使用会把规范化的来源记录为活动 `DSH_HOME`，原样使用其 `allowBuilds` 且不创建副本；启动时会验证该记录，目录被移动或失去读取权限后会重新进入选择页。全新开始不需要来源，并可使用相同的两种目标位置。选择页首先解释来源类别；点击继续后用“直接使用／导入或复制到独立环境”选项替换说明，独立操作再进入目标目录步骤，直接使用则开始使用所选目录。只有直接使用官方来源时才提示两个应用可能修改同一目录；社区桌面版直接使用不做“双方”描述。全新开始直接进入目标目录步骤。动画在同一右侧区域切换，非活动面板不可交互；仅第二步起显示上一步。问号弹窗会随当前的来源、使用方式或目标位置步骤重建对照内容。全部九种桌面语言均包含这些文案。来源最终验证失败后允许修正重试；最终选择前不修改用户数据。

社区复制保留同机插件部署，不使用官方白名单。复制器校验文件、保留权限、重新定位内部链接并拒绝外部链接。复制模式跳过自动预置与恢复安装。用户须先关闭来源应用；前后清单能发现已观察到的写入，但不是文件系统快照。Windows junction 仍需原生平台验收。

完成首次设置后，“通用设置”会提供范围更窄、只做切换的控件。它可以选择当前构建的独立 home、经识别的官方 home、经识别的自定义 home，或通过 Electron 原生目录选择器选一个空文件夹创建新配置。已有 home 与空文件夹是两种不同权限。渲染层接收的是与用途及当前 renderer 绑定、五分钟过期且不可伪造的选择标识，而非可以自行构造的路径；Electron 会在原子替换设置记录并请求完整重启应用前再次解析已有目录或检查空目录。新的空文件夹 home 使用持久化的 `created` 模式，使下一次启动可以在其尚无可识别数据时完成初始化，随后沿用普通的 Profile 修复与预置插件安装流程。切换不执行复制、合并、移动、覆盖或删除。启动时显式设置的 `DSH_HOME` 继续拥有最高优先级，并隐藏该控件。

## Alternatives considered

**把“自行导入”增加为第四种数据策略：** 否决，因为目录位置与数据共享方式是两个独立决定。始终显示的数据来源面板可以开放自定义路径，无需建立语义完全相同的第二种导入模式。

**默认 `~/.dsh` 不存在时隐藏导入与复用：** 否决，因为默认位置缺失不能证明用户从未使用 DSH。已有来源类别始终保留目录选择入口，不要求默认位置已有数据。

**接受任意非空目录：** 否决，因为无关文件不能证明目录是可用的 Harness home，并会把本可立即修正的错误推迟到导入或启动阶段。

**通过复制或移动数据来切换：** 否决，因为这属于迁移，需要处理冲突、回滚和部分复制语义，与选择 Harness 应打开哪个现有 home 无关。目录切换只改变持久化指针。

## Consequences

- 没有官方 DSH 数据的首次用户仍能看到支持语言切换的选择页，并可直接进入全新配置。
- 使用默认或自定义 Harness home 的用户都能选择独立导入，或明确共享所选目录。
- 独立导入与全新开始都能使用应用默认位置或用户选择的空目标目录，同时不放宽来源校验。
- 用户选择 home 上级目录时，只要其中 `.dsh` 包含可识别数据，就会自动解析到该子目录。
- 只有不受支持文件的目录不能导入或直接使用。
- 自定义复用路径会持久保存，但目录移动或权限撤销后必须重新选择来源。
- 已有环境无需重新运行首次导入即可再次打开，同时各自的会话、设置、插件和安全状态仍相互隔离。
- 空的自定义目录可以成为一套新的独立环境，而无需改变应用自有默认 home；非空目录会被拒绝，不会遭到覆盖。
- 切换必须完整重启桌面应用，因为 Harness 进程、Profile 管理器、命令行入口和浏览器会话都会在应用启动时绑定所选 home。

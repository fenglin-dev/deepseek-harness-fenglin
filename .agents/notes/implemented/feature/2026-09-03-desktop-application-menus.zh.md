# Agent Note: 统一桌面命令与平台原生应用菜单

Status: implemented

[English](2026-09-03-desktop-application-menus.md) | 中文

## 问题

默认 Electron 菜单暴露框架名称，并且缺少桌面恢复命令。标题栏渲染器中的纯 Web 菜单无法超出原生 36 px 边界。重启与退出命令也需要与现有桌面生命周期操作共用修改保护。

## 决策

桌面宿主持有一套白名单命令注册表与平台菜单模板。macOS 使用系统菜单；Windows 与 Linux 通过标题栏按钮请求原生弹出菜单。此设计保留[原生渲染器隔离](../architecture/2026-08-31-desktop-titlebar-webcontents-isolation.zh.md)，其内容约束和清理规则继续有效。标题栏 preload 只接收展示状态并提交已知菜单组及窗口操作，不暴露 Harness 桥。弹出菜单与客户端回执通道校验所属渲染器。

客户端报告语言与连接就绪状态，并对固定导航命令发送回执。工作区导航负责“新对话”；设置导航负责插件目标。通用设置消费一次性的目录选择与更新目标，诊断页接受快照子区域。设置项缺失时报告错误，不安装插件。断线时禁用导航。命令重新检查实时状态，重启或退出拒绝打断正在进行的修改，包括现有 Profile 租约。编辑操作指向原始内容；缩放不会改变标题栏。

Linux 使用中性窗口按钮，不依赖全局菜单。确认托盘创建失败时，禁止后台隐藏启动，并把关闭隐藏替换为取消或退出对话框。Tray 构造成功不代表图标可见；偏好保留原值，并说明对桌面环境的依赖。

macOS 开发模式使用项目本地、ad-hoc 签名的 Electron 副本，仅修改 Bundle 显示名称。安装包显示元数据使用同一产品短名。应用标识、受管数据路径和已保存自定义图标的归属保持不变。

## 考虑过的替代方案

**在标题栏视图中放置下拉 HTML。** 原生视图边界会裁切菜单。把视图扩大到 Harness 上方会破坏隔离保证；原生弹出菜单保留该保证。

**修改共享 Electron 或重命名应用标识。** 共享二进制还服务其他项目，标识变化可能影响用户数据或升级行为。缓存的开发包装层只改变展示，不改变这些身份。

**模拟点击或安装缺失的目标插件。** DOM 选择器使菜单依赖插件布局；自动安装超出导航请求的范围。固定服务导航与明确的页面缺失错误保留用户意图。

## 影响

宿主负责命令可用性和生命周期保护；客户端插件负责原有页面。原生菜单状态增加了 IPC 与订阅清理要求。没有原生菜单翻译的语言回退为英文。保留的修改租约会阻止退出，直到持有者完成或被确认已退出；格式错误或不可读取的租约需要调查，不能不安全地关闭。

## 验证

针对性测试覆盖平台模板、发送者检查、有界弹出坐标、实时状态拒绝、仅内容编辑和缩放、导航及托盘失败保护。隔离 Electron 冒烟测试使用真实视图边界、原生菜单构建、受限标题栏 preload 和内容缩放，不加载用户 Profile。Windows 显示缩放与托盘恢复、GNOME/Wayland、KDE Plasma、X11 及 macOS 安装版菜单展示仍属于原生发布验收；本地模拟平台测试不能替代这些检查。

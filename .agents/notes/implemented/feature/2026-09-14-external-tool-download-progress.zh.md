# Agent Note：外部工具下载进度仅用于观察

状态：已实现

[English](2026-09-14-external-tool-download-progress.md) | 中文

## 问题

桌面用户安装 Codex 或 Claude Code 时，在受控 Profile 修改完成前只能看到没有细分的忙碌按钮。仓库响应慢或发生重试时看起来像卡死，且只有失败后才能查看更多诊断信息。

## 决策

现有受控安装器仍是修改、重试、超时、隔离与失败判定的唯一拥有者。主 pnpm 步骤可将 NDJSON 写入 Host 在选定 DSH home 内创建的 `0600` 权限边车文件。Host 把该流解析为粗粒度阶段，只有 pnpm 确定已解析依赖总数后才提供百分比，保留容量受限且经过敏感信息清理的终端记录，并通过 Host 签发的安装 id 与不透明字节偏移提供增量读取。边车路径从不暴露给渲染层；操作结束，或下次启动发现文件过期时，Host 会删除它。

「外部工具」页面在现有安装按钮内渲染所报告的状态，并通过独立的次级按钮打开记录。关闭记录不会取消安装，百分比暂时不变也不会产生新的失败判定。

## 考虑过的替代方案

**为每个阶段设置固定权重。** 依赖解析与生命周期脚本没有真实且统一的耗时比例；加权进度看似精确，实际是编造。

**每次安装快照都返回完整记录。** 重复传输量会随安装增长，并让普通状态轮询耦合可能敏感的原始子进程输出。

## 后果

用户可以区分准备、依赖解析、下载、安装与验证，并在重试发生时查看记录；失败后仍保留原诊断。缓存命中的软件包也计为已取得依赖。Windows 重试会重置确定进度，不沿用旧尝试的百分比。进度观察是可选能力：私有边车文件创建失败时，安装本身仍可继续。

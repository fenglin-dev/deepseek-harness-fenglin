# Agent Note: 桌面渲染能力在授权前询问用户

Status: implemented

[English](2026-09-06-desktop-renderer-permission-consent.md) | 中文

## 问题

桌面宿主此前除安全剪贴板写入外，会拒绝所有渲染进程权限。依赖标准 Web API 的功能因此会在用户有机会批准麦克风、摄像头、位置、屏幕捕获、设备、局域网或文件系统访问前直接失败。

## 决策

Electron 主进程只接纳来自当前受监管 Harness 精确回环来源、且名称已识别的权限。安全剪贴板写入继续静默处理；其余接纳的能力均进入串行原生确认框，在用户允许前保持拒绝。授权只在当前渲染进程与 Harness 来源的内存中有效，导航、重启或进程退出都会清除。Chromium 能识别媒体类型时，麦克风与摄像头分别使用独立授权键。未知权限、外部来源、普通子框架及打开外部资源的能力继续安全拒绝。

macOS 安装包声明麦克风、摄像头与使用期间位置说明，使应用确认后可以继续进入操作系统授权。该机制不提供通用权限 IPC，也不允许渲染代码指定可信来源。

## 考虑过的替代方案

**允许 localhost 的所有请求。** 回环来源本身不足以证明设备或数据访问合理，仍须取得用户明确同意。

**持久保存授权。** 持久授权可能比发起请求的插件或页面存活更久。仅限当前运行期的授权可让组合变化及后续启动重新接受检查。

## 后果

标准 Web 功能可以在实际使用时请求受支持能力。并发的相同请求共享一次决定，不同请求按顺序展示；拒绝不会影响应用其他功能。应用确认之后，系统仍可能继续显示平台权限框或设备选择器。

# Agent Note：选中文字操作保持为仅草稿行为

Status: implemented

[English](2026-08-26-selected-text-actions.md) | 中文

## 问题

只读的对话与工具输出经常需要复制片段，或把片段带入另一条 prompt。既有的消息级复制按钮不能覆盖局部文字；使用原生划选后再寻找输入框，又会丢失上下文并增加重复导航。

## 决策

Web bundle 默认加入一个仅浏览器端的划选操作插件。布局把对话列和详情列标记为有效区域；插件拒绝交互元素的后代，以及任何跨越区域边界的 Range。鼠标主键划选后在 Range 附近出现横向工具条，右键则在指针处出现竖向圆角菜单；两种表现共享同一份已捕获选区和操作实现。

“复制”写入精确的选中文字。“在新对话询问”连接当前工作区的空白“新会话”，填入本地化的 Markdown 引用草稿并打开，但不发送。“添加到当前对话”把 Markdown 引用追加到当前草稿。当输入框不能接受编辑时，尤其 DSH 正在等待审批或回答时，“添加”会直接消失而不是禁用；每项操作在写入前都会再次检查运行条件。

当受信任的 Electron preload 提供受限重启方法时，右键菜单底部会在分隔线后增加“快速重启”。它与设置页和原生菜单共用受保护的桌面生命周期，因此正在执行插件变更时仍可拒绝重启。鼠标主键划选工具条和普通浏览器模式不显示这个桌面专属操作。

## 曾考虑的替代方案

**只使用浏览器原生右键菜单：** 否决。Web 无法一致地向该菜单加入应用操作，而且原生菜单不提供鼠标主键划选工具条。

**在每种消息与工具渲染器中分别注册操作：** 否决。片段选区可能跨越嵌套渲染节点，这会在相互独立的视图中重复实现事件监听、定位和关闭逻辑。

**等待交互时把“添加”显示为禁用：** 否决。人类正需要回答阻塞 DSH 的交互时，不可用操作只会增加噪声；隐藏后只保留能够完成的操作。

## 影响

- Electron 与 `dsh web` 共用划选和草稿行为；只有 Electron 会通过受信任 preload 投影“快速重启”。
- 设置、导航、编辑器、输入控件与第三方菜单继续保留原生划选和右键行为。
- 人类检查并发送生成的草稿前，不会发生模型请求。
- 首版不提供触摸长按操作，也不开放第三方操作注册表。

# Agent Note: 配置目录内的 pnpm 缓存

Status: implemented

[English](2026-09-08-profile-local-pnpm-store.md) | 中文

## 问题

Profile 位于用户主目录之外的磁盘时，pnpm 默认的同卷缓存选择可能在磁盘根目录创建 `.pnpm-store`。只更改缓存选项可能让已安装插件遇到 `ERR_PNPM_UNEXPECTED_STORE`。

## 决策

CLI 包管理器为插件操作、修复和快照安装选择解析后的 DSH 主目录内的 `.pnpm-store`。显式进程参数指定 store；pnpm 和 npm 配置环境变量将该选择传递给嵌套安装器。选定的 pnpm 可执行程序在 15 秒限制内解析带版本号的 store 路径。

对于相同 store 格式且虚拟依赖树真实位于 Profile 内的安装，包管理器只原子更新 `.modules.yaml` 的缓存位置记录。已有包文件、构建结果、锁文件和共享旧缓存保持不变。符号链接形式的元数据会被拒绝。store 格式变化和外置虚拟依赖目录继续由 pnpm 执行普通兼容性检查，不会静默重写其位置。

## 考虑过的替代方案

**程序安装目录：** Program Files 可能要求提升权限，macOS 应用包则带有签名。可写的配置主目录能够跟随用户选择的数据磁盘。

**强制重装或复制共享缓存：** 重装可能中断正常插件并需要联网；复制整个共享缓存会重复存储其他项目的数据。重新绑定缓存保留已落盘的依赖树，不放宽构建授权。

## 影响

缓存以配置主目录为单位，而不是以 Profile 或应用版本为单位。切换主目录会选择另一份缓存。共享旧缓存不会自动清理，缓存缺失仍需要本地归档或经授权的网络访问。真实内置 pnpm 回归测试覆盖同格式重绑定、离线冻结安装、添加/卸载和主目录切换；损坏元数据和外置 store 检查保持明确。Windows 磁盘路径仍需原生 Windows 验证。

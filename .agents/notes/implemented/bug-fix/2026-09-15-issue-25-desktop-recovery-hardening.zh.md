# Agent Note：Issue 25 桌面恢复链路加固

状态：已实现

[English](2026-09-15-issue-25-desktop-recovery-hardening.md) | 中文

## 问题

Issue 25 包含三个彼此独立的故障：本机 Web 端口变化时，绑定 authority 的认证 Cookie 会不断累积，最终可能让 Electron 主页面请求超过服务端请求头限制；同盘相对 `link:` 依赖在候选目录的深层路径中生成，激活把 `node_modules` 移到较浅的活动 Profile 后链接失效；恢复模式中的插件变更若检查或激活失败，可能遗留由当前桌面进程持有的候选事务和 Profile 租约。

## 决策

每次使用新的启动令牌交换认证前，桌面端只删除自身 Electron Session 中与 BrowserAuth authority Cookie 精确格式匹配的 Cookie。可信回环 Harness 来源的主页面 HTTP 失败会转换为有分类的恢复错误，重试会重新执行认证交换。

候选事务修改活动依赖前，会解析指向外部依赖的符号链接并将其改为稳定的绝对目标。完全位于候选 `node_modules` 内部的链接保持不变并随整棵依赖树一起移动。目标缺失时会在活动状态改变前失败。原始本地包规格保持不变，不会被转换成 registry 包。

恢复插件清单把能够唯一归因的插件排在最前。恢复模式持有的候选状态若检查或激活失败，桌面端会先回滚它并释放恢复租约，再返回原错误；如果回滚本身失败，会明确报告并保留恢复证据。

## 考虑过的替代方案

**删除全部 Electron Session 数据。** 这会同时删除无关站点状态，把能够精确识别的 Cookie 累积问题当成大范围用户数据损坏处理。

**只缩短 Cookie 有效期。** 这只能推迟触发请求头上限，无法约束短时间频繁重启造成的累积。

**激活后用 pnpm 重新生成全部依赖。** 这会在活动状态改变后增加网络访问和构建脚本执行。只稳定外部链接的范围有限，并能保留已经验证过的候选环境。

**禁止卸载健康插件。** 恢复界面仍是通用的人工工具，因此保留健康插件的卸载能力；将诊断归因项置顶并增加明确警告，可以降低误操作而不剥夺用户选择。

## 结果

旧的桌面认证 Cookie 不再随随机回环端口无限累积，无关 Cookie 不受影响。同盘本地插件能够承受候选目录到活动目录的层级变化。恢复尝试失败后，不会再因为当前进程遗留的 `preparing` 事务阻塞后续插件操作。本修复没有修改任何第三方插件源码。

# Agent Note：Windows 内置插件归档路径迁移

状态：已实现

[English](2026-09-15-windows-bundled-archive-relocation.md) | 中文

## 问题

pnpm 会使用正斜杠序列化 Windows `file:` 归档规格。候选激活却用本机反斜杠前缀比较这些字符串，因此候选目录删除后，内置插件引用可能仍指向临时 `plugin-transactions/<profile>/<id>/candidate` 路径。后续插件安装会在解析已有内置依赖时失败，即使用户请求安装的插件本身没有问题。

## 决策

归档迁移根据路径文本选择 POSIX 或 Windows 解析规则，不再比较本机分隔符前缀。它会改写 manifest 值及 pnpm 元数据键和值中直接位于归档目录下的 `.tgz`，而无关的本地、Git、registry 和嵌套路径保持原样。

候选准备还会识别由旧版有效事务 ID 拥有的归档引用。只有对应保留归档是常规文件时，才会把失效引用改到持久 `bundled-plugins` 目录。修复发生在新候选内部，因此重试失败不会改变活动 Profile；校验与激活成功后，修复后的元数据会与用户请求的插件一起发布。

registry 添加操作即使成功退出，只要没有声明并实体化所请求的软件包，仍会校验失败。此类候选会回滚，不会交给桌面端激活和重启。

## 考虑过的替代方案

**替换每个包含 `plugin-transactions` 的字符串。** 未采用，因为用户拥有的本地路径也可能包含相同文本。迁移只接受精确受管事务布局和有效事务 ID 下的直接归档。

**在重试 pnpm 前修改活动 Profile。** 未采用，因为修复或安装失败会在候选回滚之外改变正在运行的 Profile。在候选中修复能够保留现有事务保证。

**重新安装全部内置插件。** 未采用，因为经过验证的归档已经存在于持久 home 中。重新安装会增加不必要的软件包管理操作，并可能需要联网。

## 结果

Windows 候选激活不再遗留指向已删除事务目录的 pnpm 规范化归档路径。受影响版本创建的 Profile 会在下次受管插件修改时于保留归档存在的情况下自行修复。归档缺失或不是直接文件时仍会停止而不猜测替代项，且没有修改任何第三方插件源码。

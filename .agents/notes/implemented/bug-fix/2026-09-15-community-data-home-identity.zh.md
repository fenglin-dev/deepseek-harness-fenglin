# Agent Note: 社区配置目录身份识别

Status: implemented

[English](2026-09-15-community-data-home-identity.md) | 中文

## Problem

首次启动选择页原先会把任何包含可识别 DSH 文件的目录当作可复用的社区桌面数据。其他桌面发行版也可能使用这些通用文件，但携带不兼容的 Profile、插件或桌面状态。直接复用官方数据还会让桌面端专用变更影响官方环境。

## Decision

首次启动选择页只允许导入官方 DeepSeek Harness 数据。主进程验证 Harness home 中存在本发行版的 `.open-deepseek-harness-desktop.json` 身份文件，或存在指向该 home 的有效旧版 `data-home-setup.json` 记录后，会直接接受社区数据。含有可识别 DSH 数据但两种记录都不存在的目录，会进入原生确认框，询问它是否来自旧版 Open DeepSeek Harness Desktop。用户确认后，主进程签发短期不透明来源标识，并在最终提交时再次验证。直接复用随后通过原子写入身份来采用来源；复制不会修改来源，只会标记目标。

来源选择使用原生目录选择器签发的不透明记录，最终确认会重新验证声明的来源类别和身份状态。损坏的身份文件、其他发行版的身份 schema 以及无效旧版设置记录都是权威失败，不能进入兼容确认。已有设置中直接复用官方 home 的记录仍可兼容读取，但选择页和渲染进程协议无法再创建这种记录。

## Alternatives considered

**静默识别通用 DSH 文件。** 这种方式兼容范围较大，但无法区分本应用与其他社区桌面发行版，也不会向用户呈现兼容风险。

**复制所有选中的目录。** 这种方式避免直接共享，却会无谓复制已经验证的社区桌面 home，并移除用户明确选择复用的流程。

## Consequences

官方导入不会修改来源目录。没有产品证据的旧版社区 home 在用户明确确认来源后仍可使用，代价是应用无法独立证明该声明。损坏或外部身份仍会关闭兼容路径；手工添加 marker 不代表兼容性保证。

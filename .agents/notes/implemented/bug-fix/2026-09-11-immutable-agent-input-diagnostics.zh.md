# Agent Note: 不可变 Agent 输入诊断

Status: implemented

[English](2026-09-11-immutable-agent-input-diagnostics.md) | 中文

## Problem

外部插件即使能够成功安装并激活，也可能因为修改 `agent/pre-step` 发布的深度冻结消息而让所有对话失败。依赖与 Loader 检查无法观察这种契约违规，只读属性异常只会在用户开始一轮对话后出现。

## Decision

Profile 检查会对直接启用的外部 Bundle 根目录执行有界词法扫描，不执行插件代码，也不跟随依赖目录或源码符号链接。发布的 JavaScript 文件若同时订阅 `agent/pre-step` 并直接给 `text`、`content` 或 `messages` 赋值，就会产生归属于该 Bundle 的提示性诊断 `profile.immutable-agent-input-mutation`。当运行时证据可用时，分类器会把对应的只读属性 TypeError 映射到同一诊断码。

静态证据不能证明接收者身份，因此绝不会授权自动隔离。诊断会建议更新、停用或卸载被归属的插件。离线诊断演练样本会复现不安全监听器，但不会参与启动预装或在线更新选择。

## Alternatives considered

**按名称识别本次报告的软件包。** 软件包白名单会漏掉分支版本或后续插件中的同类契约违规，并在上游修复后留下过时的产品策略。

**自动隔离所有词法匹配。** 压缩或打包文件可能把无关字段赋值放在事件注册旁边，因此仅凭源码证据不能安全移除已安装插件。

**停止冻结 Agent 输入。** 可变共享消息会让一个监听器静默改变其他监听器和模型请求看到的内容，从而削弱所有插件共同遵守的事件契约。

## Consequences

Doctor 和实时插件清单可以在首次受影响对话之前给出警告，并在不运行插件的情况下标出直接外部 Bundle。该检查有意限制范围，可能漏掉动态构造的注册或隐藏在辅助函数中的修改；真实出现的匹配 TypeError 仍可正确分类。聚焦测试固定责任归属、误报边界、只读异常分类、打包样本完整性以及演练后活动 Profile 的恢复行为。

# Agent Note：带版本的自定义提示词

状态：已实现

[English](2026-09-20-versioned-custom-instructions.md) | 中文

## 问题

用户需要为所有对话或仅为某个桌面 Workspace 添加额外提示词。复用 Agent 预设会把执行能力与用户风格混在一起；把说明文件写进仓库则会修改用户项目，并可能让本地偏好进入版本控制。只在设置中保存一个可变字符串，也无法证明先前模型请求实际接收了哪份文本，更无法在导出诊断时做出明确的隐私选择。

## 决策

`custom-instructions` 设置命名空间拥有一份全局不可变版本历史、按已注册 Workspace id 区分的版本历史，以及 Session 诊断导出偏好。只有第一方设置页和 Workspace 控件是编辑入口；不向 Agent 或插件发布管理 API。每次保存非空文本都会追加版本，保存空文本会停用该范围；Workspace 权威删除成功后，才删除它的编辑器历史。

Host 在 `agent/created` 时注册由设置驱动的运行时上下文贡献项。全局贡献项位于 Workspace 文件说明之后，匹配的 Workspace 贡献项位于全局之后。Workspace 身份要求 Session 的 `cwd` 与已注册 Workspace 路径相等；没有匹配项的会话只接收全局说明。贡献项在请求组装时读取当前版本，因此修改从下一次获准的模型请求生效，不改写先前事件。运行时上下文快照会记录每次请求实际使用的范围、版本 id 与文本，使主会话、子 Agent、Agent Team、IM 和自动化等共用 Agent 路径的入口均可在恢复和 Session 详情中还原。

除非用户本次明确选择或先前已选择包含，否则 Session 诊断会排除自定义提示词明文。确认弹窗可以准确记住“包含”或“排除”任一选择；记住“包含”时会警告用户，设置页也可恢复为再次询问。Host 侧导出脱敏会把自定义提示词快照 section 替换为保留版本 id 的标记，绝不修改持久化数据。社区桌面版的一般设置复制、备份、恢复和迁移会同时携带版本与偏好。

## 考虑过的替代方案

**写入项目说明文件。** 拒绝，因为应用偏好不应修改仓库或通过版本控制泄露。

**把自定义文本放入 Agent 预设。** 拒绝，因为预设描述 Agent 的组成与能力，而自定义提示词是可独立分范围的用户指导。

**只保存最新文本。** 拒绝，因为这会使先前 Session 的行为无法归因，诊断也不能确认实际使用的版本。

**向插件暴露通用提示词管理服务。** 拒绝，因为这是用户偏好入口；扩大写权限会允许无关插件静默修改所有后续请求。

**诊断导出始终包含提示词明文。** 拒绝，因为诊断归档经常需要交给支持人员，其中可能包含私密项目上下文。

## 结果

提示词优先顺序明确为：平台与安全说明、Agent 预设、Workspace 文件说明、全局自定义提示词、Workspace 自定义提示词。用户自定义文本不能覆盖系统、安全或开发者权限。每个范围的单个版本最多 32,000 字符。即使 Workspace 或编辑器历史被删除，历史 Session 快照仍会按设计保留模型可见文本。由于 Workspace 采用精确路径归因，在尚未设计更宽泛映射策略前，从未注册子目录创建的会话只接收全局范围。

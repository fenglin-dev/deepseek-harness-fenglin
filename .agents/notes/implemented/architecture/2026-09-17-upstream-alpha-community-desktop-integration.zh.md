# Agent Note: 将上游 alpha 运行时与社区桌面端职责整合

Status: implemented

[English](2026-09-17-upstream-alpha-community-desktop-integration.md) | 中文

## Problem

上游 alpha 运行时同时改变了 Profile 启动、Agent 创建、Session 事件、PTC、Workflow、MCP、终端归属和归档会话恢复，而社区桌面端负责安装、Profile 事务、诊断、预装插件、手机布局和原生打包。整体替换任一侧都会丢失必要行为，或留下只在开发环境可用、安装版会失败的路径。

## Decision

社区桌面端采用上游运行时包及其公开 API，同时保留 Electron Host、安装器、数据目录选择、诊断工作区、下载策略、候选事务管理器、预构建 Profile 部署和响应式客户端外壳。仓库内消费者统一使用异步 Agent 创建、当前 Session 事件、MCP v2 资源以及当前 PTC 和 Workflow 服务。

普通 Profile 启动区分必需插件与可选插件。必需服务、根配置、变更恢复和锁失败会进入诊断模式。可选插件激活失败会显示包名和阶段，但不会隐藏其他方面可用的客户端。桌面候选操作比普通启动更严格：指定包版本、Bundle 注册和激活必须全部通过才能提交，目标失败时恢复受管依赖文件和 seed marker。市场自有命令继续在普通写锁下修改活动 Profile，并保留市场自己的结果检查和重启确认流程。

已归档会话包拥有唯一的设置页注册，使用上游 Workspace 恢复操作，同时保留分组列表、标题与 id 搜索、Workspace 筛选以及单项和批量恢复。新建桌面 Profile 选择官方终端，并通过 Better Sidebar 已发布的配置关闭重复终端；导入和复用 Profile 保留已有设置。DeepSeek 官方会话事件上报保持默认开启，“模型”页面准确说明可能包含的内容类别，并允许通过设置服务关闭；自定义提供方不会收到该扩展。

安装版 Profile 资格验证会安装全部桌面预设的原始发布归档、签名原生资源、迁移封装后的依赖树、运行 Doctor、启动普通 Harness 与客户端，并离线移除一个插件。用户实时 Patch 文件采用精确路径的 stat 轮询，不再监听整个目录树，因此大型 pnpm Profile 不会耗尽安装版进程的文件描述符额度。

## Alternatives considered

**用上游外壳替换社区桌面端。** 未采用，因为上游外壳不负责社区安装器、更新源、数据目录身份、候选回滚、诊断恢复、预构建 Profile 和手机布局。

**保留旧运行时并复制部分 alpha 功能。** 未采用，因为 Agent、Session、MCP、PTC、Workflow 和终端改动构成同一运行时包图；部分复制会形成不受支持的 API 组合。

**为兼容性修改第三方预设插件。** 未采用，因为桌面端交付维护者发布的原始归档。不兼容的预设应升级到已发布兼容版本，或从新的默认集合移除；用户已有安装仍按可选插件失败展示。

**把所有可选插件失败都视为候选失败。** 未采用，因为无关可选插件不应回滚已成功验证的目标操作。

## Consequences

源码合并在采用上游运行时包图和默认行为的同时，保留社区桌面端能力。安装版资格验证现在能发现源码构建不易暴露的问题，包括 Profile 路径迁移和文件监听压力。可选插件不再使每次普通启动都失败，但诊断模式仍负责核心与事务故障。候选回滚只保护受管插件状态，绝不恢复会话、凭据或业务数据。正式发布前仍需取得各平台原生安装包证据，并为新桌面版本建立对应的外部工具兼容清单。

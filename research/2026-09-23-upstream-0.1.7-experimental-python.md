# Upstream 0.1.7 experimental capabilities and Python packaging

Checked on 2026-09-23 against official `dsh-v0.1.6-alpha.2`, `dsh-v0.1.7-alpha.1`, and `dsh-v0.1.7-alpha.2` tags. There is no stable `dsh-v0.1.7` release in the [official release list](https://github.com/deepseek-ai/deepseek-harness/releases); “0.1.7” below means the two published alpha tags.

## Findings

- The new experimental capability is voice input/transcription. The [0.1.7-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.1) describe a first-use local recognition-model download. The new [experimental package list at alpha.2](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.7-alpha.2/packages/experimental) contains the speech service, SenseVoice provider, API, client UI, and bundle; the [0.1.6-alpha.2 package list](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.6-alpha.2/packages/experimental) does not.
- SenseVoice inference uses `sherpa-onnx-node@1.13.8`, not Python: see the provider [package manifest](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.7-alpha.2/packages/experimental/speech-to-text-sensevoice/package.json) and [official provider documentation](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.7-alpha.2/packages/experimental/speech-to-text-sensevoice/README.md). That documentation explicitly says users need no Python or compiler, and that activation does not download assets. Explicit preparation fetches revision-pinned model files, verifies sizes and SHA-256, and reuses verified files after retries. A configurable `modelOrigin` selects a Hugging Face-compatible download origin; existing model paths can be supplied instead.
- The voice model is a separate, larger asset: the same [provider documentation](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.7-alpha.2/packages/experimental/speech-to-text-sensevoice/README.md) estimates about 239 MB for INT8 weights or 938 MB for FP32, plus runtime and VAD. It lists native-package targets as macOS arm64/x64, Linux glibc arm64/x64, and Windows x64; Windows ARM64 and Linux musl are not verified targets. Bundling a Python interpreter would not eliminate the voice-model download.
- The pre-existing experimental Python PTC runtime remains a **separate optional capability**. Its [0.1.6-alpha.2](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.6-alpha.2/packages/experimental/ptc-runtime-python) and [0.1.7-alpha.2](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.7-alpha.2/packages/experimental/ptc-runtime-python) package trees have identical `py/` content (Git tree SHA `17f1b25b830eb0bb777276ad2eaaa1ee95a8dd29`). The only change in `src/index.ts` between those tags is a queue-slot typing/assignment cleanup near `replyQueue`; there is no new Python interpreter or wheel requirement in that diff. Package version numbers were updated with the release.
- The [0.1.7-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2) focus on UI, plugin-registry selection, connectivity, and dependency-update policy. They announce no additional experimental Python feature. The alpha.1 notes also mention a Playwright startup fix, which is unrelated to Python provisioning.

## Packaging implication

Upstream 0.1.7 does **not** add a technical requirement to preinstall Python for newly introduced experimental capabilities. An on-demand Python download or user-selected interpreter remains technically viable for the existing Python PTC capability, but adopting it in the community desktop requires changing its current packaging and runtime lookup; upstream does not provide that community-desktop migration. Voice input needs its own Node-native dependency and model-download plan, independent of the Python choice. This is an implementation inference from the cited manifests and provider contract, not an upstream packaging recommendation.
